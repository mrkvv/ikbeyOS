Курсовая АПС

Дорогие коллеги! Предлагаю вам следующий невероятный план по разработке нашей "ОС".

Рекомендуется взять Индивидуальное задание № 5 (из №4-6) по след. причинам:
1. Планировщик flat + preemptive RMA проще, чем POSIX (задание №6)
2. Управление ресурсами PIP уже описано в спецификации (PIP_GetRes, PIP_ReleaseRes)
3. Стандартный механизм событий, нет прерываний
Короче это золотая середина: не слишком сложно, но и не на дебила.


Вариант структуры проекта по аналогии с ChaOS, ибо он брат (близкий прототип)
├── inc/
│   ├── os.h               // API для пользователя (ActivateTask, GetResource...)
│   ├── task.h             // внутренние структуры задач
│   ├── resource.h         // PIP для ресурсов
│   ├── event.h            // события, принадлежащие задаче
│   └── config.h           // конфигурация (MAX_TASKS=32, MAX_RES=16, MAX_EVENTS=16)
├── src/
│   ├── os.c               // StartOS, ShutdownOS
│   ├── task.c             // ActivateTask, TerminateTask, Schedule, Dispatch
│   ├── resource.c         // PIP_GetRes, PIP_ReleaseRes, InitRes
│   ├── event.c            // SetEvent, WaitEvent, GetEvent, ClearEvent
│   └── port.c             // (?)переключение контекста (зависит от архитектуры)
├── tests/
│   ├── test_scheduling.c  // проверка RMA, preemptive
│   ├── test_pip.c         // проверка PIP
│   ├── test_events.c      // проверка событий
│   └── test_limits.c      // проверка макс. задач/ресурсов/событий
└── main.c                 // пример использования


Распределение задач:

Челик 1 (pup): Отвечает за планировщик + задачи. 
Делает task.c: ActivateTask, TerminateTask, Schedule (RMA, preemptive),
Dispatch (переключение контекста), очередь готовых задач

Бро 2 (mrkv): Отвечает за управление ресурсами (PIP)
Делает resource.c: InitRes, PIP_GetRes, PIP_ReleaseRes,
блокировка/повышение приоритета

Чувак 3 (arty): Отвечает за управление событиями
Делает event.c: SetEvent, WaitEvent, GetEvent,
ClearEvent, маски событий у задач

Амиго 4 (kirill): Отвечает за ядро ОС + тестирование
Делает os.c: StartOS, ShutdownOS
Интеграция модулей
Написание всех тестов (tests/)


Есть еще такой вот небольшой планчик по спринтам.
Не уверена, что будем пользоваться, но в условиях отсутствия понимания что он нас хотят,
выглядит очень убедительно.
Спринт в программировании - это короткий, заранее ограниченный по времени отрезок работы
(обычно от 1-й до 4-х недель) Ну у нас чуть поменьше сроки 😋

Спринт 1
1: Очередь готовых задач, ActivateTask (без переключения)
2: InitRes, структуры ресурсов
3: Структуры событий, маски
4: StartOS (базовый), ShutdownOS, сборка проекта

Спринт 2
1: Schedule (RMA), Dispatch (переключение), preemptive вытеснение
2: PIP_GetRes (повышение приоритета), PIP_ReleaseRes (восстановление)
3: SetEvent, WaitEvent (блокировка)
4: Тесты на планирование + PIP

Спринт 3
1: TerminateTask
2: Проверка вложенных захватов (запрещены)
3: GetEvent, ClearEvent
4: Тесты на события + интеграционные тесты

Спринт 4
Отладка, проверка ограничений (32 задачи, 16 ресурсов, 16 событий), финальный отчёт
